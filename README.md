# 120 Days of SDE Interview Preparation

A structured, daily preparation log covering Data Structures & Algorithms (C++), 
Full Stack Development, CS Fundamentals, System Design, and Applied AI, built 
one day at a time as part of a 120 day preparation plan for Software Engineering 
roles.

This repository is not a collection of tutorials. Every file here reflects 
something actually solved, built, debugged, or understood independently, with 
a dated log for each day of the process.

---

## Purpose

This repo serves three functions:

1. **A working log**, daily proof of consistent, structured preparation.
2. **A knowledge base**, DSA solutions, full stack builds, and CS notes organized 
   by topic for quick review and revision.
3. **A portfolio artifact**, evidence of process, discipline, and problem solving, 
   not just final outputs.

---

## Repository Structure

| Folder | Contents |
|---|---|
| `dsa/` | DSA problems solved in C++, organized by topic (arrays, strings, trees, graphs, DP, etc.) |
| `full-stack/` | HTML/CSS/JavaScript/TypeScript/React/Node practice and mini builds |
| `cs-fundamentals/` | Notes and Q&A on OOP, Operating Systems, DBMS, and Computer Networks |
| `system-design/` | Fresher level HLD, LLD, and design pattern notes and exercises |
| `ai/` | Prompt engineering practice and applied AI experiments |
| `daily-logs/` | One markdown file per day of preparation, work completed, concepts understood, and open doubts |

---

## How Progress Is Tracked

Progress is tracked through `daily-logs/`, where each file documents that day's 
work across DSA, full stack development, CS fundamentals, and AI. Rather than a 
separate summary table, the daily logs themselves are the source of truth. 
Reviewing the sequence of files shows the actual trajectory of preparation, 
topic by topic, day by day.

Weekly retrospectives are included at the end of every seventh day's log, 
summarizing strengths, weak areas, and priorities for the following week.

## Philosophy

This preparation is built on a simple principle: depth over breadth, and 
understanding over completion. Every problem solved, every feature built, and 
every concept studied here is meant to be explainable from first principles, 
not just checked off a list. The goal isn't to finish a roadmap. It's to be 
genuinely ready for a technical interview at the end of it.

---

If you're reviewing this repository as part of an application or interview 
process, feel free to explore any folder. Every piece of code here was written 
and understood independently, and I'm glad to walk through the reasoning behind 
any of it.
